# P0 + P1 总结：对话记忆到底有没有解

- 日期：2026-11-01
- 覆盖实验：P0（可区分性）、P0-2（投影）、P0-3（跨骨干标定）、P0-4（锚点规模）、**P1（抽取器，端到端）**
- 全部数字〔实测〕，代码与结果在 `experiments/`，语料种子固定可复现

---

## 0. 一句话回答

**有解，已经端到端跑通。** 20 段对话 → 自动抽取 → 入库 → 追问检索，**top-1 = 1.000**，全程零训练。

不是"把对话训进权重"，而是：**对话 → 带锚词的记忆条目 → embedding 层表示 → 判别投影 → 余弦检索**。
换基座时只需 96 条同分布锚点重标定，性能保持 96%。

## 1. 四个子问题的最终答案

| 诉求 | 答案 | 关键证据 |
|---|---|---|
| 记住对话里的事实与约定 | **✅ 可行** | 投影后 SNR 0.07–0.26（判据 ≤0.5）；跨骨干迁移保持率 0.96 |
| 学会我的说话风格 | **✅ 可行，但必须 4B+ 骨干** | 4B 上 C 门 0.861×（净收益）；0.83B 上 1.338×（伤 34%） |
| 自动调度（什么该常驻） | **🟡 机制成立、真模型未接线** | 玩具税 p95 145→30ms；E1 只做了干扰矩阵 |
| 让它变聪明 | **❌ 不能，且装技能会变笨** | 4B 推理探针 0.533 → 挂技能后 0.400 |

**"每次对话都训一次 LoRA"这个原始问法，答案是明确的不能**，理由已在三处独立验证：
技能压制推理（0.533→0.400）、技能间零知识迁移（只迁移格式）、通用伤害累积且"训得越熟挤占越狠"（0.83B 上单技能就 -25%）。

## 2. 证据链（四个实验各自解决了什么）

| 实验 | 问题 | 结论 |
|---|---|---|
| **P0** | 自然语言段落级记忆，能不能从一堆记忆里检索回来？ | 能，top-1 1.000，但 SNR 0.48–0.59 刚好卡在判据线上；**中层塌缩**（L8–L24 类间夹角仅 1–4°）；拉长文本无效；**锚词决定成败** |
| **P0-2** | 训练个投影能改善多少？ | SNR 压到 **0.07–0.26**，margin 提升 2–289 倍；**塌缩可被投影修复**（L18: acc 0.683→1.000）；但投影补不了信息缺失 |
| **P0-3** | MSP 跨骨干到底行不行？ | 原判"b/a 0.00–0.04"是 **acc 口径失真**（无意义映射的 acc 也有 0.983）；换 margin 口径是 **0.50–0.80**，且随锚点单调上升；**异分布锚点等于没做**（0.00 vs 0.33，差 80 倍） |
| **P0-4** | 锚点给够能到多少？ | **96 条同分布锚点 → 保持率 0.96（L0）/ 1.02（L36）**，越过 0.95 判据线 |
| **P1** | 记忆怎么自动从对话里来？ | LLM 抽取：决策条目召回 **1.000**、锚词完整率 **1.000**、端到端检索 **1.000**；规则版只有 0.550 / 0.300 / 0.550 |

## 4. 推荐架构

```
┌─ 对话发生
│    ├─→ 上下文窗口（当前任务的全部细节）
│    │
│    └─→ 记忆条目（必须含：实体 + 维度 + 取值）
│            │
│            ├─→ 表示：Qwen3-4B 的 L0（embedding 层 mean-pool）
│            ├─→ 投影：PCA 白化 k=128（零标注）
│            │        或 LDA k=8~32 λ=0.01（有配对标签时）
│            └─→ 检索：余弦 top-k + margin 阈值拒答
│
├─ 风格/工作习惯（周/月级，非每次）
│    └─→ LoRA：4B+ 骨干、r=16、全线性层、隔离挂载、滚动全量重训
│
└─ 换基座
     └─→ 96 条同分布锚点 → ridge 学 h_new→h_old → 记忆包整体带走
```

**成本**：记忆写入 = 一次 forward + 一次矩阵乘；换基座 = 一次锚点标定（3–5 万字）。
**不需要**：每次对话训练、合并 adapter、跨模型知识包市场。

## 5. 需要修正的既有结论（三处）

| 原结论 | 修正 | 依据 |
|---|---|---|
| 「E3 MSP 存亡假设 ❌ 不成立，b/a 0.00–0.04」 | **口径问题**。acc 已饱和，换 margin 口径 + 96 锚点 → **0.96** | P0-3 / P0-4 |
| 「中层塌缩，绝对不能用」 | **可修复**。配投影后 L18 的 acc 1.000、margin +0.555 | P0-2 |
| 「绑更长语义单元可拉开类间夹角」 | **无效**。105→241 字，SNR 0.493→0.482，margin 反降 40% | P0 |

保持不变的三条：锚词决定成败、拉长无用、评测必须看 margin。

## 6. 还没验证的（诚实清单）

1. **全部基于模板合成语料**，专有名词密度高于真实对话。真实场景下 acc 不会饱和（这是好事），但 margin 会更低。
2. **只测一对骨干**（Qwen3-4B → Qwen2.5-3B，跨代同族）。跨族、同代跨尺寸未测。
3. **锚点曲线未见饱和点**，96 条是语料上限，不是最优值。
4. **每折测试集只有 6–12 item**，margin 置信区间宽。
5. ~~从未用真实对话流做过端到端实验~~ → **P1 已补上**（对话→抽取→检索 top-1 1.000）。但仍有三个硬缺口：
   - 对话是模板生成的，**没有指代回跳**（"那它呢？"）和多人插话；
   - 记忆库只有 20–22 条，真实规模下检索难度高一个量级；
   - **未做冲突消解**：同一 entity+dimension 出现新 value 时（"后来改成 MySQL 了"），现在会存成两条互相矛盾的记忆。
