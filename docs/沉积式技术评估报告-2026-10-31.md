# 沉积式技术能否解决「对话即记忆」问题 · 评估报告

- 评估日期：2026-10-31
- 评估对象：`D:/WorkBuddy-works/WorkBuddy-work-1/沉积式技术/`（A 线自研 L0 + B 线 Qwen3-4B 双线，含 Node/PyTorch 两级原型）
- 评估问题：延续 2026-10-29 的议题——**能否把对话固化进模型，让它"越用越懂我"**
- 前置文档：`continual-lora/DESIGN.md`（设计方案）、`docs/沉积架构交叉评估.md`（10-29 版评估，本报告修正其中一处核心判断）

> 证据标注沿用项目惯例：**〔实测〕**=本机真实运行产出、**〔推算〕**=锚定实测的算术外推、**〔判断〕**=多证据合成。

## 0. 结论先行

**能解决一半，而且解决的正好不是最想解决的那一半。**

| 诉求 | 能否解决 | 关键证据 | 置信度 |
|---|---|---|---|
| 让模型学会我的说话风格/工作习惯（**能力记忆**） | ✅ **能**，但必须在 4B 级骨干上 | B 线 C 门 **0.861×**（装技能通用能力反升）；A 线 0.83B 同样操作是 **1.037×**（伤 3.7%）〔实测〕 | 高 |
| 记住对话里的事实与约定（**情景记忆**） | ⚠️ **技术上可行，但没人验证过** | 同骨干记忆层 a 臂 **1.000**〔实测〕；但那是 47 类单 token 寻址，不是自然语言 | 中 |
| 自动决定"什么该常驻、什么该换出"（**调度**） | 🟡 机制成立、真模型未接线 | 玩具税 p95 **145→30ms**、命中率 0.74→0.96〔实测〕；E1 只做了干扰矩阵 | 中 |
| 让它变聪明（**智力提升**） | ❌ **明确不能，且装技能会变笨** | 4B 探针 0.533 → 挂 Sedu 后 **0.400**，chat 口径掉到随机 0.250〔实测〕 | 高 |

一句话：**这个项目证明的是"技能可以作为可插拔沉积物装上、隔离、不互相破坏"，也就是程序性记忆做成了；而"对话记忆"这条线（MSP）跨骨干已死、同骨干活着但没接线。**

## 1. 先把"解决问题"拆开

原始诉求「每次对话都当作一次训练」里混了四件不同的事，它们的可行性差了一个数量级。分开谈才有意义。

| 编号 | 诉求 | 本质 | 归属 |
|---|---|---|---|
| Q1 | 记住"上次那个方案定了 A 不是 B" | 情景记忆 / 事实 | 外挂记忆层 |
| Q2 | 说话像我、按我的格式输出 | 程序性记忆 / 风格 | 参数（LoRA） |
| Q3 | 什么时候该用哪个技能 | 调度策略 | 调度器 |
| Q4 | 变聪明 | 推理能力 | 预训练 + 后训练范式 |

沉积式技术对四者的覆盖极不均匀，下面逐条给证据。

---

## 2. Q4 智力：明确不能，而且这条最硬

这是本次评估里最不该含糊的一条，因为它决定了整个系统的定位。

### 2.1 本地探针实测〔实测〕

程序生成的题目、代码判分、四选一、随机基线 0.25：

| 被测 | 口径 | 总体 |
|---|---|---|
| L0 0.83B | 3-shot 60 题 | **0.283** |
| Qwen3-4B base | 3-shot 60 题 | **0.533** |
| **Qwen3-4B + Sedu 技能** | 3-shot 60 题 | **0.400 ↓** |
| Qwen3-4B + Sedu 技能 | chat 32 题 | **0.250 = 纯随机** |
| Qwen3-4B-Instruct-2507 | chat + 写过程 | 0.625 |

**最硬的一条**：同一个 4B，挂上技能 adapter 后通用推理探针从 0.533 掉到 0.400。技能注入不仅不提升推理，还压制通用解题行为。

这与 E1 的"技能间零迁移"是同一件事的两面：适配器学的是"输出该技能的词表答案"，在开放推理题上就是干扰。

### 2.2 补充发现：4B 的推理完全依赖显式思维链〔实测〕

| 设置 | 四步应用题（12 题） |
|---|---|
| 允许写过程，给 400 token | **1.000（12/12）** |
| 禁止写过程，只回字母 | **0.000（格式失败率 100%）** |
| 两步题 + 禁止写过程 | 0.250（58% 格式失败） |

这条比准确率本身更重要：**这个量级的模型没有"隐式推理"**，它的思考就是吐出来的 token。所以"生产级智力"必须靠长链 RL 后训练（Qwen 自己用这条路把 AIME 从 19.1 拉到 81.3），不是靠往上面贴技能。

### 2.3 对记忆系统的直接含义

如果为了让模型"记住我的偏好"而频繁注入窄技能，代价是**通用推理能力被压制**。这是"每次对话训一次"最致命的反面证据——不是记不住，是记住了会变傻。

## 3. Q2 风格/技能：能做成，但有骨干容量门槛

这是本项目的正面成果，且已经过线。

### 3.1 两条线的验收都在同一套口径下通过〔实测〕

| 项 | A 线 0.83B | B 线 Qwen3-4B |
|---|---|---|
| D1 验证 ppl | 56.9 | **16.76** |
| D2 A_tf / A_gen | 0.973 / 0.880 | **0.994 / 0.960** |
| **C 门（通用 ppl 回归）** | **1.037×**（伤 3.7%，靠校准步从 1.338 压下来） | **0.861×（反而变好）** |
| 技能沉积物单个体积 | r8 = 12.1 MiB（1 GB 装 84 个） | 同量级 |

### 3.2 关键分水岭：骨干容量决定"装技能要不要付代价"

同一种操作，在 0.83B 上吃 -25% 通用能力（r16 时 1.338×，截到 r2 仍是 1.218×，救不回来），在 4B 上却是净收益（0.861×）。

**这不是调参差异，是容量差异。** 由此得到一条可以直接写进设计的原则：

> **骨干必须显著大于技能的信息量。** 否则每加一个技能，都是在从通用能力里抢参数。

对"持续学习"的直接含义：**小模型天生不适合做持续学习**，它没有余量。要做，就把底座换大。

### 3.3 三个死结论，不必再试

项目已经用真实参数把这些路封了〔实测〕：

| 路线 | 实测结果 | 判决 |
|---|---|---|
| 多技能 ΔW 算术相加 | 保真 0.13–0.57 | 禁止叠加，必须隔离挂载 |
| 一个学生拟合多教师 | r16 0.23–0.62；r48+温度KD 仍 0.41–0.80 | 禁止融合，一技能一沉积物 |
| 低秩截断当压缩 | 保真几乎免费（r2 = 1.008），但通用伤害只从 1.338 降到 1.218 | 截断可行、但不能当"省伤害"的手段 |

### 3.4 一个反直觉但重要的正面结果：技能之间零破坏〔实测〕

B 线三技能（Sedu/Nuri/Tavi）交叉测试：

- **破坏率全负**：挂任何技能都不会让别的技能变差，交叉准确率**高于**裸基座（裸基座 0.333/0.366/0.364 → 挂载后交叉 0.588–0.684）；
- 但**格式迁移率只有 0.39–0.50**，且迁移的只是"用短答案收尾"这个格式习惯，没有词表映射的迁移。

读法：**技能可以安全共存，但别指望它们互相帮忙。** 这正是隔离挂载在模型层面成立的依据——不是工程妥协，是模型本身的性质。

## 4. Q1 事实记忆：这里我要修正上一轮的判断

### 4.1 上一轮我说错了什么

10-29 那份评估里，我基于玩具尺度 b/a=0.94 判断"MSP 才是每次对话的正确载体"。**真骨干上这个数字是 0.000–0.043，等于机会水平（0.021）。**

| 臂 | Qwen2.5-3B → 自制 L0（真骨干对） |
|---|---|
| a 联合上限（同骨干本地坐标训练） | **1.000** |
| b ISA 转译（跨骨干 + 同分布锚点标定） | **0.000 / 0.043** |
| b0 不转译（随机投影） | 0.029 / 0.043 |
| 机会水平 | 0.021 |

**b ≈ b0 ≈ 机会**：转译带来的信息量为零。换同族骨干（Qwen2.5-3B ↔ Qwen3-4B）重测，b/a 仍只有 0.03–0.04〔实测〕。两组骨干、两种族系，结论一致。

机制已被量化，不是猜的：

| 量 | 值 |
|---|---|
| 不同 prompt 的 hidden 类间平均余弦（Qwen） | 0.974 → **类间夹角 13.2°** |
| 标定图保真度（余弦 0.964–0.979） | **误差夹角 11.7–15.4°** |
| 误差 / 类间 夹角比 | **≈ 0.9–1.2** |

判别要求"误差夹角 ≲ 类间夹角的一半"，这里误差和类间**一样大**，所以任何线性标定都不可能区分类别。玩具能到 0.94，是因为玩具的键近乎正交（夹角 ≈ 90°），10° 误差完全可以容忍。

### 4.2 但精确的读法是：死的只有"跨骨干"，不是"MSP 本身"

这一点必须说清楚，否则会误杀整条路。

- **a 臂 = 1.000** 证明：记忆层本身完全够用，槽容量不是瓶颈，能承载骨干完全没有的知识（裸答 0.02 → 1.000）。
- **b 臂 = 0.00** 只说明：**记忆包不能跨骨干搬运**。

而"每次对话写记忆"这个诉求，**根本不需要跨骨干**——记忆包和宿主用同一套坐标，a 臂就是这条路的上限，而它是 1.000。

所以正确的表述是：

> **MSP 作为产品（跨模型知识包市场）死了；MSP 作为机制（同骨干外挂记忆层）活得很好，只是没人接线。**

### 4.3 还开着的那道门，以及它的具体风险

同骨干记忆层唯一没验证的是：**真实自然语言的键，判别性远低于单 token 置换。**

E3 用的键是"单 token → 单 token"的秘密置换，键空间近乎正交。真实对话的键是"上次那个方案"「按之前说的」这类高度含糊的指代，类间夹角会小得多，信噪比可能跌破 1。

项目自己给出的两条救法，正好指向正确的设计方向：

1. 把标定误差压到 ≤3°（cos ≥ 0.999）—— 需要逐层标定 + 非线性探针，难度高；且同骨干场景下**根本不需要标定**，所以这条对本议题不适用；
2. **把记忆槽绑到更长的语义单元（段落级/答案集级），让类间夹角从 13° 拉开** —— 这条才是关键。

第 2 条与"对话记忆"的形态天然吻合：一条对话记录本来就是一个长语义单元，不是单个 token。**所以本议题的设计不应照抄 E3 的单 token 协议，而要改用"整段对话 → 一段记忆"的粒度重测。**

### 4.4 顺带一条对实验设计的警告

锚点**分布**比**数量**重要得多：同分布锚点标定余弦 0.977，换 200 条通用语料掉到 0.640（检索@1 = 随机）。

这解释了为什么玩具的"锚点漂移曲线"（4→0.10 … 48→0.96）在真骨干上复不出来——它测的是"同分布锚点的数量效应"，不是"任意锚点的覆盖效应"。以后任何涉及标定的实验，锚点必须与目标域同分布。

## 5. Q3 调度：机制成立，真模型侧还没接线

- 玩具尺度〔实测-引用〕：200 轮 Zipf 负载下常驻命中率 **0.74→0.96**、加载税 p95 **145→30ms**、任务分不降反升（0.262→0.282）。
- 真模型侧〔实测〕：E1 只做到"干扰矩阵"，**"使用统计 → 蒸馏 → 晋升 → 回归"的闭环没接线**；竞价仲裁在 L0 上没有可仲裁对象（KV cache 虽已实现，但本机瓶颈是 CPU 逐算子调度而非重算，cache 无提速）。
- 一条被证实的工程结论：本机解码的真提速手段是**左填充批量生成（7.7×**，1707ms → 223ms），不是 KV cache。代价是批量与逐条在 20 token 后会有分歧（fp16 批量核数值差），需标注"非逐位可复现"。

判断：Q3 是**工程量问题，不是可行性问题**。1–2 天的接线活，不是研究风险。

## 6. 对"每次对话训一次"的最终裁决

用这次的新数据重新算一遍，结论比 10-29 更硬。

**每次对话训一次 = 每次给基座贴一个窄映射 + 每次挤掉一点通用能力 + 每次都不可撤销。** 四重代价叠加，而收益是"这一次对话的几十条信息"，这些信息用日志或记忆层存下来的成本接近零。

新增的三条量化反驳：

1. **技能压制推理**：4B 探针 0.533 → 0.400。贴的窄技能越多，模型越"只会干那件事"。
2. **技能间零知识迁移**：学 Sedu 不会让 Nuri 变好，只迁移格式习惯（0.39–0.50）。所以每场对话单独训一个 adapter，彼此不会累积成"更懂我"，只会累积成"更多个互不相干的映射"。
3. **通用伤害是累积且不可逆的**：0.83B 上单个技能就吃掉 22–34%，且项目实测"训得越熟，挤占越狠"。一百个技能叠加的结局不需要实验就能推出来。

**正确的形态**（本次证据支持）：

| 层 | 载体 | 频率 | 证据 |
|---|---|---|---|
| 事实、约定、偏好条目 | 同骨干记忆层（MSP 形态） | 可随对话写入 | a 臂 1.000〔实测〕 |
| 语言风格、格式习惯 | LoRA，**在 4B 级以上骨干** | 周/月级 | C 门 0.861×〔实测〕 |
| 通用推理 | 不碰 | — | 探针会掉〔实测〕 |
| 调度 | 使用统计驱动换入换出 | 持续 | 玩具 145→30ms〔实测〕 |

## 7. 三条可以写死的设计原则

1. **骨干必须显著大于技能。** 0.83B 上装技能伤 3.7%（校准后），4B 上是净收益。做持续学习，先换底座。
2. **参数学"怎么说"，记忆层存"说了什么"，两者永不混用。** 技能注入对另类任务零迁移，这是模型性质，不是训练技巧问题。
3. **任何跨表示空间的搬运都必须行为级校验。** b0 臂"不标定直读 = 0.029"与卡芙卡项目"PEFT 键名不匹配只发 UserWarning、评分 0.394 = 基座 0.394"是同一类失败：系统不报错，只静默地什么都不做。

## 9. 如果继续往下做：最小验证路径

按"能不能决定生死"排序，不是按工作量。

| 优先级 | 动作 | 为什么先做 | 成本 |
|---|---|---|---|
| **P0** | **同骨干、段落级记忆层实验**：把 E3 的 a 臂改成"整段对话 → 一段记忆"，键用真实自然语言，测寻址准确率 | 这是 Q1 唯一的活门。单 token 置换的 1.000 不能外推到自然语言，必须用真实粒度重测 | 1–2 天 |
| P1 | 记忆槽容量曲线：M 个槽能装多少条对话才饱和 | 决定淘汰策略（复用沉积的风化机制） | 1 天 |
| P2 | E1 闭环接线（使用统计→晋升→回归） | Q3 是纯工程，但没它整个系统只是"能装"，不会"自己长" | 3–5 天 |
| P3 | 4B 上跑 C 门 + 隔离挂载的多技能轮换 | 验证"多个风格 adapter 轮换"在 4B 上是否仍零破坏 | 1 天 |

**P0 的具体设计建议**（避免重蹈单 token 协议的坑）：

- 键：一段 200–500 字的真实对话记录；值：该记录对应的一条结构化记忆（如"项目 X 的部署方案定为 A"）。
- 类目数 ≥ 30，保证类间夹角有统计意义；同时**必须报告类间夹角与检索误差夹角的比值**，而不只报准确率——因为 13.2° vs 12–15° 这种对比才是可解释的量。
- 必须含"近似键"对照（同一件事的两种说法），测的是自然语言记忆真正需要的鲁棒性。

## 10. 诚实清单：本报告不能证明什么

1. **玩具尺度（d=96）的所有绝对数字不外推**，只取机制方向。
2. **E3 的 1.000 是 47 类单 token 寻址**，不是自然语言记忆；真实 b/a 与真实 a 臂都未测。
3. **"技能压制推理"只在 Qwen3-4B + Sedu 这一组上测过**（n=60/32），未做多技能叠加的剂量-反应曲线。
4. **加载税 145→30ms 是玩具调度器上的数**，真模型侧未接线，不能当作已实现的能力。
5. **本项目从未做过"对话级"的持续学习实验**——所有 D2/E1 实验都是"预先造好的技能数据"，不是"从真实对话流中提取的样本"。这一点差异很大：真实对话的样本质量方差远高于自造数据。

## 11. 一句话收尾

这个项目用两个月把"技能可插拔"从主张做成了有数字的工程事实，同时诚实地杀掉了自己方案里的三条乐观分支。**它没有解决"记住每次对话"，但它把这个问题从"要不要每次都训"逼成了"事实该放记忆层、风格该放参数、而记忆层只能在本机坐标里用"。**

剩下那个 1–2 天的 P0 实验，才是这条路上唯一还开着的门。
